Visão Geral
A
MisticPay
é uma API completa de pagamentos que permite receber e enviar pagamentos via PIX de forma simples e segura. Nossa plataforma oferece:
Receber Pagamentos (Cash-In)
Gere QR Codes PIX e receba pagamentos de seus clientes instantaneamente
Realizar Saques (Cash-Out)
Transfira fundos para qualquer chave PIX de forma programática
Webhooks em Tempo Real
Receba notificações automáticas de mudanças de status em suas transações
Versão da API
Esta documentação refere-se à API v1. Todas as requisições devem ser feitas para o endpoint base:
https://api.misticpay.com
Autenticação
Conceito
A API da MisticPay utiliza autenticação baseada em
Client ID + Client Secret
. Existem duas formas de credencial, e a diferença entre elas é o que cada uma alcança.
Chave de acesso (recomendada)
Par
pk_…
/
sk_…
, emitido no painel em
API → Chaves de Acesso
. Viaja no header
Authorization
no formato
Basic
e carrega escopos escolhidos por você na criação. É a única credencial que alcança toda a API — inclusive saque.
O
sk_
aparece
uma única vez
, no momento da criação. Ele não fica guardado em formato legível em lugar nenhum, nem do nosso lado: se perder, revogue a chave e crie outra.
Credencial ci/cs (legada)
Par
ci_…
/
cs_…
nos headers
ci
e
cs
. Continua funcionando, mas apenas em dois endpoints:
Endpoint
ci/cs
Chave de acesso
POST /transactions/create
Sim
Sim
POST /transactions/check
Sim
Sim
Todos os demais endpoints
Não
Sim
Uma credencial ci/cs em qualquer outro endpoint responde
403
. Saque, saldo, consulta de conta, listagem de transações, cripto e MED exigem chave de acesso.
Desligamento em 30 de setembro de 2026
A partir dessa data a autenticação por
ci
/
cs
deixa de funcionar, inclusive nos dois endpoints acima. Migre para chave de acesso antes disso.
Importante
Nunca exponha seu Client Secret no frontend ou em repositórios públicos. Ele deve ser armazenado de forma segura no backend.
URL Base da API
Todas as requisições devem ser enviadas para a seguinte URL base:
URL Base
https://api.misticpay.com/api
Headers Obrigatórios
Headers HTTP
Copiar
Authorization: Basic BASE64(client_id:client_secret)

Content-Type: application/json
BASE64(client_id:client_secret)
é o par unido por dois pontos e codificado em base64 — o mesmo esquema do HTTP Basic. Em Node:
Buffer.from(`${clientId}:${clientSecret}`).toString("base64")
. A maioria dos clientes HTTP monta isso sozinha: no
curl
,
-u client_id:client_secret
.
Migrando de ci/cs
No painel, acesse
API → Chaves de Acesso
e clique em
Criar Chave de Acesso
. É exigido código 2FA.
Marque apenas os escopos que a sua integração usa. Escopo não é editável depois: ampliar exige criar outra chave e revogar a antiga.
Copie o
sk_
na hora — ele não é exibido de novo.
Troque os headers
ci
/
cs
pelo header
Authorization: Basic …
nas suas chamadas.
Revogue a credencial ci/cs quando não houver mais tráfego nela.
Os endpoints, os corpos de requisição e os formatos de resposta não mudaram — apenas a forma de autenticar.

POST
/api/transactions/withdraw/qrcode
cashout
Paga um QR Code Pix a partir do código "copia e cola". O valor será debitado do saldo disponível.
Somente QR Code estático.
QR Codes dinâmicos (de cobrança) são recusados com HTTP 422, porque o valor deles é definido pelo recebedor no momento da liquidação e pode mudar depois da validação. Os dados do QR são apurados pelo servidor e revalidados imediatamente antes do pagamento.
Parâmetros
Parâmetro
Tipo
Descrição
qrCode
*
string
Código Pix copia e cola (BR Code).
amount
number
Obrigatório apenas quando o QR Code não define valor. Se o QR já traz valor, este campo é ignorado — e se divergir do valor do QR, a requisição é recusada com HTTP 409.
description
string
Descrição do pagamento (opcional)
projectWebhook
string
URL do webhook para notificações (opcional)

Solicitar saque crypto
POST
/api/crypto/withdraw-api
cashout
Solicita um saque em criptomoeda (USDT BEP20) para uma wallet. O valor será debitado do saldo disponível e convertido para USDT.
💡 Informações importantes:
Valor mínimo: R$ 20,00
Valor máximo: R$ 3.000,00
Taxa da plataforma: 5% sobre o valor
Taxa de rede: variável (calculada automaticamente)
Wallet deve ser válida no formato BEP20 (0x...)
Parâmetros

*
string
Endereço da wallet BEP20 para receber USDT (formato: 0x seguido de 40 caracteres hexadecimais)
projectWebhook
string
URL do webhook para notificações (opcional)

  --data '{
  "amount": 100,
